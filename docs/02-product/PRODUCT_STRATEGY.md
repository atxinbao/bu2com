# BU2 产品战略 v0.1

## 1. 产品愿景

让 AI Agent 在人的控制下获得可用、有限且可审计的经济权限。

BU2 长期希望成为 AI Agent 的商业账户，统一承载：

- Agent 身份与责任主体
- 预算和消费权限
- 支付授权与执行
- 任务级费用归因
- 交易和交付凭证
- Agent 信誉与商业记录

## 2. 当前产品切口

BU2 首先是 **Agent Budget Control**，不是完整钱包。

首版解决已经存在的问题：团队同时使用多个模型、搜索服务、数据接口和云资源，但只能看到供应商账单，无法将费用稳定归属到具体 Agent、项目和任务。

首版价值主张：

> 为每个 Agent 分配预算，用确定性规则控制费用，并生成任务级审计记录。

## 3. 产品原则

### 3.1 先治理，后支付

没有预算、权限和审计，支付只会放大风险。BU2 先建立控制层，再接入真实支付通道。

### 3.2 模型提出理由，规则决定权限

大模型可以解释为什么需要购买，但不能自行改变金额上限、商户范围或审批规则。

### 3.3 默认最小权限

新 Agent 默认没有真实支付权限。预算、商户、用途和有效期必须被明确授予。

### 3.4 任务是最小归因单元

每笔费用必须关联到 Agent 和任务。只有供应商维度的账单不构成 BU2 的核心价值。

### 3.5 协议中立

BU2 兼容不同模型、Agent 框架和支付协议，不与底层支付网络竞争。

### 3.6 证据优先

费用记录不仅包括金额，还应保留授权依据、策略判断、支付结果和交付状态。

## 4. 产品范围

### 4.1 MVP 范围

- 工作区和成员
- Agent 账户
- 项目和任务
- 虚拟预算
- 确定性消费策略
- 支付申请
- 人工审批
- 费用导入或 API 上报
- 任务级账本
- 基础成本分析
- 一个受控的 x402 沙盒或小额验证闭环

### 4.2 MVP 明确不做

- 法币或加密资产托管
- 用户提现
- 代币交易、理财或投资建议
- 通用加密钱包
- 自动开放信用额度
- Agent 自行修改策略
- Agent 市场和信誉排名
- 完整发票、税务和会计系统
- 消费者端“万能 AI 钱包”

## 5. 阶段路线

| 阶段 | 产品能力 | 商业目标 | 进入下一阶段的门槛 |
| --- | --- | --- | --- |
| P0 验证 | 原型、访谈、手工费用归因 | 确认高频问题 | 3 家团队愿意试点 |
| P1 MVP | 虚拟预算、策略、审批、账本 | 获得首批付费客户 | 5 家活跃试点、2 家付费 |
| P2 支付 | x402、非托管连接、签名收据 | 验证真实支付需求 | 真实交易成功率与风控达标 |
| P3 企业化 | 团队权限、财务集成、AP2 | 提升客单价 | 稳定续费和企业采购需求 |
| P4 网络 | Agent 收款、信誉、服务发现 | 建立网络效应 | 双边供需形成 |

## 6. 核心假设

| 编号 | 假设 | 风险 | 验证方式 |
| --- | --- | --- | --- |
| H1 | 团队需要 Agent 级费用归因 | 只有大客户才在意 | 访谈和账单复盘 |
| H2 | 预算控制比事后报表更有价值 | 用户只想看成本 | 原型任务测试 |
| H3 | 开发者愿意接入 SDK 或 MCP | 集成成本过高 | 30 分钟接入测试 |
| H4 | 企业愿意为审计记录付费 | 现有 FinOps 已够用 | 试点报价 |
| H5 | 真实 Agent 支付会形成需求 | 市场成熟过慢 | x402 小额闭环 |

## 7. 北极星价值

BU2 的北极星不是“管理了多少钱”，而是：

> **完成费用归因并通过策略治理的有效 Agent 任务数。**

它同时反映 Agent 活跃度、预算使用、策略执行和任务闭环。
