# BU2 Task-first P0 正式用户测试方案（已废止）

> 本方案对应已废止的 Task-first 定位。当前原型验收请使用 [Transaction-first P0 验收方案](TRANSACTION_P0_ACCEPTANCE.md)。

日期：2026-09-01  
执行者：Codex  
版本：v1.0

## 1. 测试目标

验证目标用户能否在没有产品人员解释的情况下，通过 BU2 完成以下闭环：

```text
发现异常任务
  → 理解实际成本与重试浪费
  → 识别治理模式和命中策略
  → 做出批准、拒绝或调整控制条件的决定
  → 确认状态、费用和账本语义同步
```

本轮验证产品理解与交互，不验证真实支付、资金托管、供应商账单准确性或生产策略网关。

## 2. 目标参与者

招募 5–8 名高频 Agent 用户，每人满足至少三项：

- 每周使用 Codex、Claude Code、ChatGPT 或类似 Agent 不少于 4 天。
- 同时使用两个以上模型、工具或 Agent 平台。
- 管理多个项目、客户或自动化工作流。
- 曾遇到费用无法归因、异常重试或额度快速消耗。
- 负责团队预算、项目交付或 Agent 运行质量。
- 能接受 API、SDK 或 MCP 形式的接入。

优先覆盖三类角色：Operator、Manager、Owner/Viewer。避免只邀请产品设计者、BU2 项目参与者或已经熟悉演示路径的人。

## 3. 测试设置

- 单人远程或现场测试，每人 30–40 分钟。
- 使用桌面浏览器，统一从 Tasks 首页开始。
- 使用全新页面会话，避免继承上一位参与者的决策状态。
- 参与者可以选择中文或英文，测试过程中不切换语言，语言切换单独验证。
- 主持人只读任务卡，不解释页面、字段或正确路径。
- 经参与者同意后记录屏幕、语音、点击路径和完成时间。

## 4. 主持人开场脚本

> 这是一个用于管理 Agent 执行成本的产品原型。这里的数据均为演示数据，不会发生真实付款。请像使用真实工作产品一样操作，并说出你正在寻找什么、如何理解页面以及为什么做出决定。测试对象是产品，不是你；遇到困惑请继续表达，但我不会提示具体操作位置。

开场只提供以下背景：

> 你负责一个同时运行编码、研究和自动化 Agent 的团队。你需要确认是否存在异常支出，并决定是否允许相关任务继续执行。

## 5. 正式测试任务

### UT-01 识别工作重点

任务卡：

> 你刚开始今天的工作。请判断当前是否有需要你处理的 Agent 任务，并说明你为什么优先处理它。

观察点：

- 是否从 Tasks 开始。
- 是否注意到需要人工处理数量。
- 是否找到 TASK-2048 或另一项异常任务。
- 是否使用实际成本、重试浪费、策略结果或状态作为判断依据。

通过标准：90 秒内找到一项待处理异常，并能说出至少两个异常信号。

### UT-02 解释任务费用

任务卡：

> 打开“修复支付回调竞态条件”，说明这项任务已经花了多少钱、浪费了多少、为什么暂停，以及继续执行可能增加多少费用。

正确理解：

- 实际成本：¥18.64。
- 重试浪费：¥6.82，浪费率 36.6%。
- 暂停原因：异常重试策略触发。
- 新增授权上限：¥4.20。
- 预计最终成本：批准后为 ¥22.84，但新增授权不是已发生费用。

通过标准：参与者不需要提示即可正确区分实际成本、新增授权和预计最终成本。

### UT-03 理解治理模式

任务卡：

> 判断 BU2 是否能在这项任务中的所有资源调用发生前阻止费用，并说明依据。

正确理解：任务为混合模式；模型和部分工具属于强控制，Browser MCP 等资源属于观察模式，只能调用后入账和告警。

通过标准：参与者明确回答“不能控制所有调用”，并能在资源层找到至少一个强控制和一个观察模式资源。

### UT-04 处理异常

任务卡：

> 在不改变后续同类任务规则的前提下，允许当前任务继续，但最多新增 ¥4.20。

观察点：

- 是否进入 Exceptions。
- 是否确认异常原因、浪费和预计追加费用。
- 是否理解影响范围为“仅当前任务”。
- 是否选择“批准继续”。

通过标准：两分钟内完成正确操作，无误点“调整控制条件”或另一条异常。

### UT-05 验证决策结果

任务卡：

> 确认刚才的决定已经生效，并说明哪些数字发生了变化、哪些没有变化。

正确结果：

- 全局待处理数量从 2 变为 1。
- TASK-2048 状态变为“继续执行”，策略结果变为“已批准”。
- 实际成本仍为 ¥18.64。
- 新增授权为 ¥4.20。
- 预计最终成本为 ¥22.84。
- 决策出现在任务治理记录或时间线中。

通过标准：参与者能确认至少四项同步结果，并且不把 ¥22.84 描述为已发生费用。

### UT-06 检查另一项异常

任务卡：

> 查看“同步竞品定价数据”的异常，说明它与刚才处理的异常有什么不同，以及 BU2 现在还能做什么。

正确理解：该任务为观察模式，费用已经发生；BU2 可以关闭当前任务、记录异常或为后续同类任务增加强控制，但不能追回或阻止已经完成的调用。

通过标准：参与者选择到 EXC-388，并正确描述观察模式的事后治理边界。

### UT-07 语言切换

任务卡：

> 将界面切换到另一种语言，确认当前页面、状态、按钮和费用字段是否仍然能理解。

通过标准：一次点击完成切换；除专有名词、ID、金额、模型名和供应商名外，没有非目标语言的界面文案。

## 6. 结束访谈问题

按顺序询问，不引导答案：

1. 你会用一句话如何描述 BU2？
2. 哪个页面或信息最有价值？为什么？
3. 哪个字段最难理解？
4. 你是否信任 BU2 给出的允许、暂停或拒绝结果？还缺少什么证据？
5. 哪些调用必须强控制，哪些可以只观察？
6. 你希望首先接入哪个 Agent、模型或工具？
7. 你愿意为费用归因、异常控制、预算预测或统一结算中的哪一项付费？
8. 如果明天可以使用，你会邀请谁一起使用？
9. 什么原因会阻止你安装 SDK、API 或 MCP 接入？
10. 在你的真实工作中，单任务、每日、重试和预算提醒阈值会如何设置？

禁止直接询问“你喜欢这个产品吗”；优先追问最近一次真实费用问题和现有解决方式。

## 7. 单场记录表

每位参与者记录：

| 项目 | 记录内容 |
| --- | --- |
| 用户编号与角色 | 不记录不必要的个人身份信息 |
| 当前 Agent 工具 | 工具数量、使用频率、项目数量 |
| 当前费用管理方式 | 账单、表格、平台额度或没有管理 |
| UT-01 至 UT-07 | 成功、提示后成功、失败、不适用 |
| 完成时间 | 每项任务开始至完成的时间 |
| 错误点击 | 点击位置和参与者预期 |
| 关键原话 | 关于价值、困惑、信任和付费的原话 |
| 购买信号 | 主动询问接入、试点、价格或团队邀请 |
| 阻塞项 | 安全、隐私、权限、接入成本或数据准确性 |

评分：成功 2 分，提示后成功 1 分，失败 0 分；单人满分 14 分。

## 8. 产品验收标准

### 8.1 核心可用性门槛

正式通过必须同时满足：

- 至少 80% 参与者在无提示下完成 UT-01 至 UT-05。
- 至少 80% 正确区分实际成本、新增授权和预计最终成本。
- 至少 80% 正确理解强控制、观察模式和混合模式。
- 至少 80% 在两分钟内完成异常处理。
- 至少 90% 的测试任务最终可以完成，允许非关键文字理解偏差。
- 任何参与者都不能因界面误导把授权额度理解为已发生费用。
- 不出现任务、异常、费用或决策关联到错误对象的情况。

### 8.2 产品价值门槛

满足以下至少三项：

- 至少 4/5 或 6/8 参与者确认任务级费用归因解决真实问题。
- 至少 60% 主动表达愿意接入一个真实 Agent 或项目试点。
- 至少 50% 能明确指出愿意付费的能力和预算责任人。
- 至少 3 名参与者提供最近三个月内真实发生的异常重试或费用失控案例。
- 至少 70% 认为 Exceptions 队列比逐次人工审批更符合工作方式。

### 8.3 语言门槛

- 中文和英文各至少由两名参与者使用。
- 两种语言的核心任务完成率差异不超过 15 个百分点。
- 不因翻译错误改变金额、策略动作、治理模式或影响范围的含义。

## 9. 不通过与停止条件

出现任一情况，暂停扩大测试并先修复：

- 两名及以上参与者混淆实际成本和新增授权。
- 任何费用或决策显示在错误任务或异常中。
- 两名及以上参与者误以为观察模式可以阻止调用前费用。
- 批准后数量、状态或账本出现不同步。
- 核心任务中出现阻断性错误、白屏或状态无法恢复。
- 测试人员需要反复解释 Tasks、Exceptions 或治理模式的含义。

## 10. 测试结论分级

- **GO**：满足所有核心可用性门槛，并满足至少三项产品价值门槛。进入真实数据接入和 P0 数据/API 契约冻结。
- **ITERATE**：核心流程可完成，但一至两个关键理解指标未达标。修订原型后补测 3–5 人。
- **STOP/REPOSITION**：少于 50% 能独立完成核心流程，或多数参与者不认为任务级费用治理解决真实问题。重新评估首发用户与价值主张。

## 11. 测试完成后的交付物

- 参与者招募与筛选记录。
- 每场任务评分和关键原话。
- 问题清单：严重度、出现人数、证据和建议修复。
- 指标汇总及 GO / ITERATE / STOP 结论。
- 经验证的术语、策略模板和接入需求。
- 进入第二轮数据模型与 API 契约的冻结输入。
