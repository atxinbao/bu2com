# BU2 指标与验证计划 v0.1

## 1. 验证目标

当前阶段不验证“Agent 经济最终有多大”，而验证三个更近的问题：

1. 团队是否存在稳定的 Agent 费用归因问题？
2. 预算和审批是否比事后成本报表更有价值？
3. 团队是否愿意为此接入并付费？

## 2. 北极星指标

**受治理的有效 Agent 任务数（Governed Agent Tasks）**

一个任务只有同时满足以下条件才计入：

- 关联有效 Agent 和项目
- 至少产生一笔费用申请或费用记录
- 经过有效预算和策略判断
- 有明确的完成、失败或取消状态
- 费用已归属到任务

## 3. 漏斗指标

```text
注册工作区
  → 创建项目
  → 创建 Agent
  → 配置预算和策略
  → 上报首笔测试费用
  → 产生首个真实任务
  → 连续 4 周使用
  → 转为付费
```

| 阶段 | 指标 | 初始目标 |
| --- | --- | ---: |
| 激活 | 15 分钟内完成首笔测试费用 | ≥ 60% |
| 接入 | 创建 Agent 后完成 SDK/MCP 接入 | ≥ 50% |
| 使用 | 周活跃 Agent / 已创建 Agent | ≥ 30% |
| 归因 | 可关联到任务的费用比例 | ≥ 80% |
| 留存 | 试点团队 4 周留存 | ≥ 60% |
| 付费 | 试点转付费 | ≥ 30% |

这些目标用于早期验证，需根据首批样本调整。

## 4. 价值指标

- 每个活跃 Agent 的有效任务数
- 每个任务的费用记录数
- 自动批准、人工审批和拒绝比例
- 预算超支前被阻止的申请数
- 失败任务成本占比
- 财务完成一次成本归因所需时间
- 用户查看审计详情的频率
- 导出账本的团队比例

## 5. 可靠性指标

- 重复费用率：目标为 0
- 预算计算差异：目标为 0
- 策略重放一致率：100%
- 决策可解释覆盖率：100%
- 被撤销凭证继续成功调用：目标为 0
- 交易与交付状态不一致率

## 6. 客户访谈计划

### 样本

- 10 名 AI 产品或工程负责人
- 8 名 Agent 开发者
- 5 名财务或 FinOps 人员
- 5 名 MCP 工具或数据服务商

### 关键问题

1. 目前如何知道某笔 AI 费用属于哪个任务？
2. 最近一次异常费用是怎样发现和处理的？
3. 哪些 Agent 支出需要事前批准？
4. 现有云成本或费用工具为何不足？
5. 为接入新的费用治理工具，最多愿意投入多少时间？
6. 哪一项能力值得立即付费？
7. 哪些数据绝不能离开现有环境？

避免询问“你会不会使用”，优先让受访者展示现有账单、流程和真实事件。

## 7. 原型实验

### 实验一：费用归因

让用户使用最近一周真实账单，尝试归属到项目、Agent 和任务。

通过条件：BU2 模型能明显减少手工整理时间，并暴露现有账单看不到的信息。

### 实验二：策略配置

让用户为一个研究 Agent 设置预算和审批规则。

通过条件：用户无需解释即可正确完成正常、超限和未知商户三种规则。

### 实验三：开发者接入

让开发者从空项目完成首笔测试费用上报。

通过条件：30 分钟内完成，且不需要 BU2 团队人工修改代码。

### 实验四：付费意愿

向试点提供明确套餐和合同，而不是口头询问意向。

通过条件：至少 2 家团队接受付费试点或签署带价格的意向协议。

## 8. Go / Iterate / Stop 门槛

### Go

- 至少 3 家团队连续使用 4 周
- 至少 2 家愿意付费
- 任务费用归因率达到 80%
- 用户同时使用预算控制和审计，而非只看报表

### Iterate

- 问题存在但接入成本过高
- 用户只使用其中一个场景
- 财务需要更强导出或私有化能力
- 开发者更偏好网关而不是 SDK

### Stop or Reposition

- 多数目标团队无法提供 Agent 级任务标识
- 费用规模不足以支持付费
- 用户只需要现有云成本标签
- 真实支付需求存在，但预算治理需求不成立

## 9. 90 天验证节奏

| 周期 | 工作 | 输出 |
| --- | --- | --- |
| 第 1-2 周 | 访谈与流程观察 | 问题证据、客户分层 |
| 第 3-4 周 | 可点击原型与规则测试 | 原型测试报告 |
| 第 5-8 周 | 轻量 MVP 与 3 家试点 | 使用数据、问题清单 |
| 第 9-12 周 | 付费报价与 x402 闭环 | 付费结果、下一阶段决策 |
