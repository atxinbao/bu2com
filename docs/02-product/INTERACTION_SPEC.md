# BU2 P0 页面与交互规格 v0.2（Task-first）

## 1. 原型目标

原型用于验证产品结构和关键决策流程，不连接真实后端、支付通道或客户数据。

核心演示路径：

```text
进入 Tasks
  → 发现异常失败任务
  → 下钻模型、工具和重试费用
  → 查看命中策略和暂停原因
  → 批准、拒绝或调整预算
  → 决策同步到任务时间线与账本
```

原型位置：`/Users/mac/Documents/bu2com/prototype`

## 2. 全局框架

### 左侧导航

- Tasks
- Exceptions
- Budgets
- Policies
- Projects & Agents
- Ledger
- Overview
- 工作区设置

当前页面使用蓝色高亮；待审批数量在导航中显示提醒。

### 顶部栏

- 当前工作区
- 页面名称
- 搜索入口
- 创建 Agent

### 响应式行为

- 桌面端显示完整侧栏。
- 小屏端隐藏侧栏，保留主要内容和顶部操作。
- 表格型内容在窄屏转为纵向信息排列。

## 3. Tasks（默认首页）

首屏展示任务名称、状态、Agent、项目、环境、实际成本、预算影响、重试费用、浪费率、策略结果、治理模式、开始时间和持续时间。

点击任务进入 Task Detail；异常任务使用醒目标记，但不依赖颜色表达唯一含义。

## 4. Task Detail

包含任务摘要、执行时间线、费用分解和治理记录四个区域。时间线串联 Spend Request、策略判断、ResourceCall、重试、审批和最终状态。

## 5. Exceptions

Exceptions 是操作队列而非普通审批列表。每项异常必须解释标记原因、已发生浪费、继续执行预计成本、允许操作和影响范围。

支持批准继续、拒绝继续和调整任务预算。决定后更新 Task Detail 时间线、治理记录、Tasks 状态和账本语义。

## 6. 治理模式

- 强控制：调用前可阻止。
- 观察模式：调用后入账与告警。
- 混合模式：按资源分别治理。

任务列表、详情和异常队列均需显示或解释治理模式。

## 6.1 费用口径

- 实际成本：已经发生并写入账本的费用。
- 新增授权：允许后续执行的额度，不计入实际成本。
- 预计最终成本：实际成本加已授权但尚未发生的预计费用。

三个字段不得互相覆盖；Tasks 与 Task Detail 必须使用同一实际成本。

## 6.2 语言

原型支持全中文和全英文即时切换。导航、页面标题、状态、按钮、治理模式、费用字段、说明和操作反馈必须使用同一语言；任务 ID、策略 ID、金额、模型名、供应商名和 Agent 自定义名称作为专有标识保持原样。

## 7. 旧版辅助页面

Overview、Projects & Agents、Budgets、Policies 和 Ledger 保留为辅助工作面，但不再是默认主流程。

## 8. v0.1 页面参考

以下章节保留为辅助页面参考，不改变 Task-first 优先级。

## 8.1 总览

### 页面目标

让 AI 产品负责人在首屏判断费用是否正常，以及是否有需要人工处理的申请。

### 首屏内容

- 本月已用预算
- 受治理任务数
- 待人工审批数
- 月度预算进度
- 自动批准、人工审批和策略拒绝比例
- 待审批申请
- 最近任务

### 交互

- 点击左侧导航切换产品页面。
- 点击“创建 Agent”打开创建弹窗。
- 点击待审批申请进入审批上下文。
- 点击“查看完整账本”进入任务与账本。

### 状态

- 正常：预算低于提醒阈值。
- 警告：预算达到 80% 或存在即将过期的审批。
- 超限：预算被冻结，新的申请被拒绝。
- 空状态：引导创建第一个 Agent 和发送测试费用。

## 4. 项目

### 页面目标

按业务项目查看 Agent 数量、预算和运行状态。

### 列表字段

- 项目名称
- Agent 数量
- 已用预算 / 总预算
- 状态

### 交互

- 点击项目进入项目详情。
- 项目详情可下钻到 Agent、任务和账本。
- 创建项目属于后续交互，不在当前原型中写入数据。

## 5. Agents

### 页面目标

管理所有受预算和策略治理的 Agent。

### 列表字段

- Agent 名称
- 所属项目
- 已用预算 / 总预算
- 状态

### 创建 Agent

点击顶部“创建 Agent”打开弹窗：

1. 输入 Agent 名称。
2. 指定所属项目。
3. 设置月度虚拟预算。
4. 点击“创建并配置策略”。
5. 原型切换到 Agent 列表；真实产品应进入策略配置步骤。

### 状态

`draft → active → suspended → archived`

被暂停或归档的 Agent 不能提交新支出申请。

## 6. 预算

### 页面目标

让管理者知道预算分配到哪里、使用了多少、何时需要干预。

### 内容

- 工作区月度总预算
- 已用和可用金额
- 项目预算分配
- 工作区硬上限
- 默认单笔上限
- 提醒阈值
- 是否允许自动增加预算

### 交互规则

- P0 原型只展示预算配置。
- 修改预算需要明确保存动作。
- 降低预算后若小于已用金额，状态变为超限，但不改写历史交易。
- 硬上限不能被 Agent 或支付适配器突破。

## 7. 策略

### 页面目标

用可解释的确定性规则控制 Agent 支出。

### 策略卡片

- 策略名称
- 作用域
- 核心条件
- 状态

### 示例策略

- 标准 API 支出：白名单商户且单笔不超过 0.50 美元，自动批准。
- 付费数据审批：单笔超过 5 美元，进入人工审批。
- 未知商户阻止：生产环境商户不在白名单，直接拒绝。
- 测试环境额度：每日不超过 2 美元，使用模拟支付。

### 交互规则

- 策略修改产生新版本。
- 发布前必须用正常、审批和拒绝案例测试。
- 新版本不重新解释历史交易。
- 下层策略只能收窄上层权限。

## 8. 审批

### 页面目标

让审批人在最少上下文切换下做出可追责决定。

### 左侧队列

- Agent
- 商品或服务
- 金额
- 触发原因
- 到期时间

### 右侧详情

- 申请 ID
- Agent 和负责人
- 项目与任务
- 商户、商品、金额和币种
- 购买理由
- 当前预算
- 命中的策略及版本
- 相似历史申请

### 操作

- 批准
- 拒绝
- 返回队列

### 反馈

批准或拒绝后：

- 按钮禁用，避免重复决定。
- 显示决定结果。
- 记录审批人、时间、原因和策略版本。
- 原型只更新当前页面状态，不产生真实费用。

## 9. 任务与账本

### 页面目标

回答每笔费用由谁、为了什么任务、根据什么授权产生。

### 列表字段

- 任务名称
- Agent
- 实际费用
- 状态

### 任务详情

- 任务目标
- 创建者和时间
- Agent 及版本
- Spend Request 列表
- Policy Decision
- Approval
- Transaction
- Delivery Evidence

### 规则

- 历史账本不能被静默覆盖。
- 退款和冲正通过新事件记录。
- 失败任务保留已经发生的费用。
- 重试费用必须可以单独识别。

## 10. 搜索

P0 搜索范围：

- 项目名称
- Agent 名称
- 任务 ID 和名称
- Spend Request ID
- Transaction ID

搜索不包含密钥、完整支付凭证或未授权工作区数据。

## 11. 关键空状态

### 无 Agent

提示创建 Agent、分配虚拟预算并发送首笔测试费用。

### 无审批

显示“当前没有等待决定的申请”，并提供策略执行统计。

### 无交易

提供 SDK/MCP 测试示例，而不是展示空白表格。

### Agent 被暂停

显示暂停原因，并禁用新支出申请入口。

## 12. 错误与恢复

- 重复幂等键：返回原申请，不创建重复记录。
- 预算不足：明确显示缺少金额和命中预算。
- 策略冲突：以更严格规则为准，并显示冲突来源。
- 审批过期：禁止继续操作，引导重新提交。
- 外部调用失败：记录失败，不标记交付完成。
- 模拟适配器异常：允许安全重试，不重复记账。

## 13. 原型验收

- 侧栏可以切换总览、项目、Agents、预算、策略、审批和账本。
- 创建 Agent 弹窗可打开、取消和提交。
- 审批可以在批准和拒绝之间完成一次决定。
- 所有费用示例都关联 Agent 和任务。
- 页面不出现真实支付、提现、兑换或资产投资入口。
- 界面明确标注 P0 Prototype。
- 桌面和小屏均保持核心内容可读。
