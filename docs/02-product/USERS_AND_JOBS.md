# BU2 用户与核心任务 v0.1

## 1. 首发客户画像

BU2 不以普通消费者作为第一批客户，而以已经产生多 Agent、多模型或多 API 费用的团队为起点。

### Persona A：AI 产品负责人

**目标：** 在不失控的前提下扩大 Agent 自动化范围。

主要问题：

- 不知道不同 Agent 的真实成本
- 无法预先限制任务支出
- 发生异常费用后难以追责
- 缺少可向管理层解释的证据

核心任务：

> 当团队部署多个 Agent 时，我希望给它们分配独立预算和权限，以便在扩大自动化的同时控制风险。

### Persona B：Agent 开发者

**目标：** 快速为 Agent 增加预算检查、审批和费用记录。

主要问题：

- 每个 API 都有不同计费和认证方式
- 需要自行实现限额与审批
- 调试时无法快速定位费用来源
- 支付逻辑与 Agent 业务代码耦合

核心任务：

> 当 Agent 需要调用付费工具时，我希望通过统一接口申请预算并记录结果，而不是重复开发财务控制逻辑。

### Persona C：财务或 FinOps 管理者

**目标：** 将 AI 费用分配到团队、项目、Agent 和任务。

主要问题：

- 供应商账单粒度不足
- 预算超支发现得太晚
- 无法区分生产任务、实验和失败重试
- 缺少标准化导出和审批记录

核心任务：

> 当 AI 费用增长时，我希望知道谁、为何、在哪个项目中产生费用，并在超支前进行干预。

### Persona D：MCP 工具或数据服务商

**目标：** 让 Agent 能够发现、购买并证明服务交付。

主要问题：

- Agent 缺少统一支付方式
- 小额 API 计费接入成本高
- 难以判断调用方是否获得真实授权
- 缺少统一收据和争议证据

核心任务：

> 当 Agent 调用我的付费服务时，我希望快速验证预算与授权，并生成可核验的交付记录。

## 3. 端到端使用故事

### 故事一：创建研究 Agent

1. 管理员创建工作区和“行业研究 Agent”。
2. 将 Agent 归属到“投资研究”项目。
3. 分配每月 100 美元虚拟预算。
4. 设置单笔上限 2 美元、每日上限 10 美元。
5. 允许搜索、模型和指定数据供应商。
6. 开发者获得 Agent Token 并接入 SDK。

### 故事二：Agent 申请付费工具

1. Agent 创建任务并说明目标。
2. Agent 提交费用申请：商户、金额、用途、商品和有效期。
3. BU2 使用确定性规则检查。
4. 规则允许则返回批准；超限则创建人工审批。
5. 调用完成后上报实际费用和交付证据。
6. 账本将费用归属到工作区、项目、Agent 和任务。

### 故事三：财务复盘

1. 财务查看本月项目预算消耗。
2. 下钻到 Agent 和任务。
3. 区分成功任务、失败任务和重试成本。
4. 查看超限申请和审批人。
5. 导出费用及审计记录。

## 4. 首批访谈筛选条件

优先访谈满足至少两项的团队：

- 已在生产或内部流程中运行 Agent
- 每月 AI/API 支出超过 500 美元
- 同时使用两个以上模型或付费工具
- 已遇到预算超支或费用归因困难
- 有财务审批或客户成本核算要求
- 正在开发 MCP 工具或付费 Agent 服务
